The Source Is the Product

From notes on WebCanBe · September 2026

A lot of website tools make editing easier by hiding the source. That trade can be useful, but it creates a boundary I keep running into: the moment the visual layer becomes the real product, the code underneath turns into an implementation detail that the user does not fully control.

While building WebCanBe, I ended up with the opposite principle: the source is the product. The visual editor, AI assistance, previews, templates, and deployment flow should all operate on the same real project rather than creating a parallel representation that is difficult to escape.

One source of truth

The architecture I keep returning to is simple to state and difficult to implement. A user should be able to click an element visually, change it, inspect the resulting source change, edit the same file directly, ask AI to modify it, and export the project without a conversion step.

That means the system cannot treat visual editing and code editing as separate modes with separate data models. The codebase has to remain the single source of truth. Visual controls become another way of producing explicit changes to that source.

Compatibility instead of pretending

Not every codebase is equally safe to edit visually. Rather than pretending otherwise, I prefer a compatibility model: some projects are ready for full visual editing, some can be previewed and edited only in code, and some need a small normalization step first.

This is less magical than claiming universal support. It is also more honest and more useful. The product can explain what it understands, what it can safely change, and what will remain untouched.

Ownership changes product decisions

If users really own the project, export should not be a transformation. It should mostly remove platform metadata and hand back the same project they have been working on. Deployment should be optional. AI should create reviewable patches. Rollback should be a first-class operation.

That principle affects nearly every layer of WebCanBe. It makes the product harder to build, but it also gives it a clearer reason to exist. I do not want visual editing to replace code. I want it to become another precise interface to the same thing.
