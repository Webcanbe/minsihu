Building a Personal AI That Can Actually Act

Started 7 Mar 2025 · expanded through 2026

On 7 March 2025 I started a long-running experiment: build something closer to a practical Jarvis-style personal AI than a normal chatbot.

The pipeline behind the assistant

The architecture grew into speech input → transcription → model/router → memory/context → queued tool actions → confirmation gates → text or speech output.

Later versions explored Groq-based speech transcription and reasoning, local and cloud model routing, memory/context storage, browser and URL actions, queued work, and explicit permission gates.

Intent is not permission

An assistant can infer that deleting a file, sending money, or changing a sensitive setting might help. That does not mean it should have silent authority to do it.

Human Approval Is a Product Feature

Returns & refunds workflow · May–June 2026

I explored a Shopify-oriented returns and refunds system where the interesting problem was not generating a refund decision. It was deciding when software should be allowed to act.

Rules first, AI second

Deterministic policy constraints should stay separate from softer model judgment. The system should expose the model suggestion, the applicable rules, and the final human action so consequential automation remains auditable.

Designing a Privileged Control Plane

WebCanBe AdminKey · August 2026

Administrative actions are different from ordinary product actions. I explored that idea through a separate WebCanBe AdminKey application rather than placing every privileged operation inside the main product.

Separate capability from convenience

The application centered on explicit operation descriptions, manifests, validation, and rendered action details. Privileged actions deserve enough friction that the operator can see what will happen, which target it affects, and whether the operation matches the intended manifest.
